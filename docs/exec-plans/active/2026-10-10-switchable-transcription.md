# マイク入力の実接続と受け入れ確認

初手は **OpenAI**。publish #12 の main を取り込み、テスト先行で OpenAI・Apple・ブラウザ音声入力を実装した。OpenAI の専用キーがなく、実認識は未確認。有料送信を始める前にここで止める。

## 目的

UDトークがないときのマイク入力と、OpenAI／Apple／UDトークの切替を実接続で確認し、利用者が merge を判断できる状態にする。

## 再開に必要な事実

- ブランチは `Eotel/self-transcription`。publish #12 の基準は `ab0943c`。単一 FastAPI と React/XState のローカル PoC。認証と字幕の永続化はない。
- 入力と資源の所有は `Connections` と `backend/app/transcription/`、公開・手修正保護は既存 Relay。ブラウザは録音の Adapter、Apple は FastAPI が所有する Swift 子プロセス。
- 現行経路・準備・上限は[マイク入力](../../microphone-input.md)、境界は[構成](../../../ARCHITECTURE.md)。候補比較は[クラウド](../../research/2026-10-10-cloud-transcription.md)と[OpenAI・Apple](../../research/2026-10-10-openai-apple-transcription.md)。
- Apple は macOS 26.6.2 / arm64、Swift 6.4、日本語モデル導入済みで合成日本語6.28秒を実認識した。背景 Chrome の合成マイクでも実 FastAPI と Swift の認識・訂正保存・観客表示・停止を確認した。物理マイクと会場条件は未検証。
- OpenAI は公式仕様に沿う模擬 WebSocket とローカル API で確認済み。日本語指定の受理、実認識、遅延、利用枠、請求は未確認。模擬結果を実接続の証拠にしない。

## 決定と制約

1. クラウドの初手は OpenAI `gpt-live-transcribe`。試験上限は **合計100円・送信合計20分以内**。エンジンと上限の再判断は不要。
2. キーはこのリポジトリ専用に用意されたものだけ。キー本文をチャット・GitHub・ログへ出さず、他プロジェクトや用途不明の継承環境変数を使わない。専用変数は `CAPTION_RELAY_OPENAI_API_KEY`。
3. 料金の基本値は USD 0.017/分。税・為替・地域処理・課金丸めをアカウントで確認し、保守的な円換算を設定する。ローカルの2倍見積もり90円と送信20分の制限は提供元の請求上限を保証しない。裏付けられなければ送信しない。
4. 使用量台帳を再起動・やり直しでリセットしない。試験はAI校正をオフにする。切断では未確定文を保持し、再開は明示操作と新しい世代を使う。音声の自動再送・別提供元への自動切替はしない。
5. PR の assignee は Eotel。CI が green になるまで確認する。merge は三浦さんの確認後。LICENSE と公開設定は別作業で、ここから変更しない。

## 残りの作業

1. PR を作成し、CI と未解決レビューを確認する。OpenAI の実接続待ちを説明に明記する。
2. リポジトリ専用キーと課金条件が準備されたら設定の受理を確認し、同意済みの短い日本語音声で認識・確定・停止を試す。送信時間と円見積もりを確認してから試験を広げる。
3. 物理マイクと会場条件で途中字幕・確定・訂正・切替・停止を確認する。同じ音声で数字・固有名詞・否定、CER、途中文と確定表示の遅延を測り、利用者へ比較結果を示す。
4. 実測結果と未確認の範囲を文書・PRへ反映する。受け入れを確認したら、この計画を削除する変更を作る。
