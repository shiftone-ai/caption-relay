# マイクから字幕を入力する

操作画面の接続設定で「独立配信」「マイク」を選び、音声認識を適用する。「認識を開始」でマイクの許可を求め、準備完了後の音声を認識する。選択・適用だけでは録音しない。停止・入力変更・ページ離脱でマイクと認識接続を閉じる。

1. 接続設定で入力元と音声認識を選び、「接続を適用」を押す。
2. マイクを選び、「認識を開始」を押す。認識中の表示を確認してから話す。
3. 字幕を訂正し、必要な文を保存する。「字幕を隠す」は認識を続けたまま観客表示を止める。
4. 「認識を停止」で最後の字幕の確定を待つ。切断時は未確定文を保持し、字幕を確認してから明示的に再開する。

ブラウザには `getUserMedia`・AudioWorklet・AudioContext が必要。localhost または HTTPS で開く。同時に開始できるマイクは1つ。開始後の機器変更は停止してから行う。UDトークへ反映する編集参加ではマイクを開始できない。

## 音声認識の準備

| 音声認識 | 必要な準備 |
|---|---|
| OpenAI | このリポジトリ用のキーと、課金条件を確認した円換算をバックエンドへ設定する。今回のキー未配置の検証では実接続・認識精度・遅延・請求を確認していない。 |
| Apple | バックエンドが動く対応 Mac、macOS 26 以降、日本語モデル、macOS 26 SDK が必要。`bash scripts/setup.sh` が Swift 補助プログラムをビルドする。Linux やモデル未導入では理由を表示する。モデルを自動ダウンロードしない。 |

Apple の音声認識は**接続先の Mac**で行う。ブラウザが別端末なら音声をその Mac へ転送する。Swift 補助プログラムはマイクを直接開かず、ブラウザから届いた音声を SpeechAnalyzer / SpeechTranscriber に渡す。アプリは音声をファイルへ保存しない。

OpenAI はバックエンドから Realtime の transcription 接続を開き、`gpt-live-transcribe`、`languages: ["ja"]`、`delay: "low"` を要求する。設定の受理を待って送信し、WebRTC VAD で無音800msまたは発話15秒を区切りとする。VAD は16kHz・20ms単位で評価する。無音だけの区切りは確定要求しない。日本語の実認識と設定の受理は専用キーによる確認が残っている。[根拠](research/2026-10-10-openai-apple-transcription.md)

## OpenAI の試験上限と設定

承認された試験は**送信合計20分・合計100円以内**。試験中はAI校正をオフにし、別の有料処理を混ぜない。キー本文をチャット、画面、ログ、Gitへ載せず、他プロジェクトのキーを使わない。通常のAI校正用 `OPENAI_API_KEY` を音声認識へ流用しない。

| 環境変数 | 用途 |
|---|---|
| `CAPTION_RELAY_OPENAI_API_KEY` | このリポジトリ専用の音声認識用キー。ブラウザへ返さない。 |
| `CAPTION_RELAY_STT_JPY_PER_USD` | 税・地域処理・為替を含む保守的な円換算。正の有限値が必要。例は [.env.example](../.env.example) のみ。 |
| `CAPTION_RELAY_STT_USAGE_PATH` | 使用量台帳の任意の保存先。未設定では利用者のキャッシュ配下 `caption-relay/transcription-usage.json` を使う。 |

起動スクリプトは `.env` を自動読込しない。[開発手順](development.md)に従い、このリポジトリ用の設定だけを起動環境へ渡す。

台帳は音声サンプル数と円見積もりだけを保存する。音声・字幕本文・キーは含めない。送信前にファイルロックと保存を完了し、再起動や再試験でも累計を保持する。無音と失敗した送信の予約分も加算する。台帳を削除・初期化して試験を再開しない。

基本料金 USD 0.017/分へ設定した円換算と2倍の余裕を掛け、円見積もり90円または送信20分を超える音声を送らない。残り10円は終了・丸めの余裕とする。台帳の破損・保存失敗でも送信を止める。**これはローカルの見積もりによる制限であり、提供元の請求上限ではない。** 利用アカウントの課金条件を確認できなければ、有料試験を始めない。[料金の根拠](research/2026-10-10-openai-apple-transcription.md)

## 入力と停止の契約

音声は同じアプリの `/api/source/audio` へ送る。接続時に同一 Origin・独立配信・マイク入力を照合し、別のマイクを拒否する。最初に選択した認識先・入力周波数・mono PCM16形式を通知する。認識先が現在の設定と一致しない場合は接続を始めない。その後は約100msの音声に連番と開始サンプル位置を付ける。バックエンドが24kHzへ変換する。

欠落、形式違反、送信の遅れ、認識エラーは停止理由を表示する。自動再接続・音声再送・別の認識への自動切替は行わない。再開には新しい発話の識別子を使い、古い接続の結果を採用しない。正常停止は末尾の音声を送り、期限内で確定結果を待つ。確定できなければ成功した停止と区別する。

認識結果は既存の `SourceEvent` へ変換する。途中結果は同じ発話の全文更新、確定は最後の全文と `is_final=true`。OpenAI の確定到着が逆順でも音声の区切り順を保持する。Apple の同じ開始時刻の範囲更新は同じ行に反映し、置き換えられた未確定範囲を撤回する。手修正の保護・確定後の自動公開・観客用データの分離は既存 Relay が判断する。

## 確認済みの範囲

macOS 26.6.2 / arm64、Swift 6.4 の実 API へ、合成した日本語音声6.28秒を実時間で渡した。途中更新から1行の確定字幕になり、数字を含む全文を観客APIへ配信できた。クラウドへの音声送信とモデルの追加導入は行っていない。

背景の Chrome では合成音声をマイク入力として使い、実 FastAPI と Swift の認識、停止後の音声トラック解放、訂正保存と観客表示、UDトークへの切替を確認した。ビルド済み画面とVite経由の音声接続を操作した。[操作画面](assets/microphone-input/operator.png)・[狭い画面の操作](assets/microphone-input/mobile.png)・[観客表示](assets/microphone-input/audience.png)と[通信・停止の記録](assets/microphone-input/verification.json)に、秘密を含まない合成字幕の確認画像を置く。物理マイク、会場の雑音、長時間運転、OpenAI の実認識、同一音声での精度・遅延比較は未検証。これらを模擬イベントのテスト成功から推定しない。
