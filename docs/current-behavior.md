# 現行 PoC の仕様

実装確認日：2026-10-24

現在のコードとテストに対応する仕様。将来の機能・受け入れ条件は [v0.2 の設計案](design-v0.2.md)を参照する。起動方法は [README](../README.md)、責務の配置は[システム構成](../ARCHITECTURE.md)に記載する。

## 提供範囲

単一の `demo` セッションでUDトークまたはマイク認識の字幕を受け取り、AIと手動で訂正する。操作画面の接続設定で「独立配信」と「UDトークへ反映（試験接続）」を選ぶ。AIは初期値オフで、キーを設定した提供元へ次の確定字幕を送る。入力と同時、または後から届く修正結果を受け取るAPIも提供する。

独立配信ではZoom形式の送信を受けて、このアプリの観客画面へ配信する。観客画面は初期設定で公開字幕を追加しながら末尾へスクロールする。過去の公開字幕を読み返せるほか、表示設定で直近1〜10件だけの表示へ切り替えられる。従来のWeb閲覧入力も環境変数による任意の経路として残す。設定・根拠・実機確認の範囲は[UDトークの入力接続](udtalk-input.md)を参照する。

UDトークへ反映するモードでは編集用URLで参加し、確定字幕だけを訂正できる。AIと明示的な手動保存の両方が、原文の再取得・編集ロック・訂正要求・ロック解除を経由する。元の断片IDを保ったまま各断片をロックし、変更箇所を順に送信する。全要求の受付前に保存成功を返さない。複数断片の送信は一括更新ではなく、一部の受付後に失敗した場合は反映済みの内容を操作画面へ取り込み、下書きを保持して再確認を促す。字幕表示はUDトーク純正を使い、このアプリの観客APIとSSEは非表示・空欄を返す。独立配信の表示設定とプレビューは使えず、純正側で確認・設定する。

形式が不正なリンクと閲覧専用リンクは、動作中の接続を止める前に拒否する。参加キーの有効性はUDトークの応答で判断する。共有情報の `sharingLimit` を端末時計と比較して接続を拒否しない。モード変更時は前の接続とAI処理を終了し、受信先の資格情報を更新する。接続の切り替え開始から完了までと、接続の終了中に届いた字幕では、新たなAI処理を予約せず原文を保持する。停止したWeb入力は接続状態を無効・受信数0として返す。履歴とブラウザの下書きは残すが、編集参加で受け取った字幕は独立配信へ切り替えても自動公開しない。現在の編集接続で受信した対象以外はUDトークへ送らない。画面の「受信中」は通信の応答を示し、音声認識や純正画面への表示を保証する状態ではない。

独立配信の「送られる字幕」は初期値を「本文のみ」とする。「発話者名と本文」を選んだ場合だけUDトークの名前付き形式を分離する。本文中に続く区切りは保持する。この設定だけの変更では送信先・受信番号・既存字幕を保持し、適用後の新しい字幕から分離する。設定値は編集参加へ切り替えても接続状態で取得でき、独立配信へ戻る際も保持する。サーバー再起動で初期値へ戻る。書式の根拠と未確認事項は[発話者名の受信](udtalk-input.md#発話者名の受信)に記載する。

状態はサーバーのメモリ上に置く。認証と永続化はなく、ローカルの単一プロセスで使う。

## 操作と編集

「準備」の「テスト字幕を送る」は検証用の発話を入力 API へ送る。現在の公開方法と非表示状態に応じた結果を送信箇所で説明する。実機の音声認識や UDトーク接続の確認にはならない。

一覧の見出しは「字幕一覧」。保存した字幕を一列で読む構成とし、原文の全文を各行に繰り返さない。本文16px・行間24px、8px単位の余白、短文の行高48pxを基準にする。読み幅は最大960pxとし、長文は折り返し、切り捨てない。操作ヘッダー、直近3件の入力と観客への表示、一覧の見出し、「最新へ」は一覧をスクロールしても残る。監視欄の長文はその欄でスクロールして読める。

一覧と直近の入力に連番を表示せず、左端に最初の受信時刻を12pxの `HH:mm` で添える。訂正欄の見出しは「字幕の訂正」とし、その横にも時刻を置く。入力ラベルは「表示文」。本文と時刻で対象を確認し、編集ボタンの読み上げ名にも本文を含める。

時刻は端末のタイムゾーンを使い、補足と読み上げ用の説明に日付・秒・タイムゾーンを含める。入力の改版、AI修正、人の保存で受信時刻は変わらない。音声の発話時刻は入力に含まれておらず、ここではサーバーが初めて受信した時刻を使う。

字幕の行をクリックして選択した字幕を独立した訂正欄に開く。原文は入力の上に表示し、長文はその欄でスクロールして全文を確認する。下書きがある場合は保存済み文を折りたたみで参照できる。編集開始時に字幕改版を保持し、最新位置への追従を止める。閉じたり別行へ移ったりしても下書きを保持し、「変更を破棄」で破棄する。未保存行も一覧には保存済み文を示し、未保存のアイコンと背景で下書きがあることを伝える。公開文が保存済み文と異なる場合は、公開アイコンの説明に公開文を含める。

履歴を確認している間の新しい字幕は件数と最初の新着の境界で示す。「最新へ」は一覧の末尾が見えていない場合だけ表示する。訂正欄・下書き・カーソル位置を保って最新位置へ移り、新着数を消して追従を再開する。「編集中の字幕へ」は、編集中の字幕が一覧の表示範囲外にある場合か、設定で訂正欄が隠れている場合だけ表示する。選ぶと設定を閉じ、下書きを保って訂正欄と履歴上の位置へ戻る。追従中は画面のリサイズや行の折り返し後も末尾へ移る。モバイルでは監視欄を横並びにし、設定・訂正中も見出し・移動操作を含む履歴全体に256pxを残す。高さ700px以下ではページ全体を縦にスクロールでき、保存・反映操作まで移動できる。DOMと視覚の順序は履歴、訂正・設定欄に揃える。

状態アイコンの説明は、アイコンまたは説明にポインターがある間と、アイコンへフォーカスがある間に表示する。画面の上下の空きに応じて配置し、履歴の下端でも切れないようにする。Escapeでフォーカスを動かさず閉じられる。編集を閉じるか下書きを破棄したら、起点の字幕へフォーカスを戻す。履歴確認中の新着件数はpolite通知で伝え、受信した字幕の全文を割り込んで読み上げない。

表示文は「保存して公開」または Ctrl / Command + Enter で保存する。未確定や公開対象外の字幕では「保存」と表示する。Enter だけでは改行し、IME 変換中のキー操作では保存しない。競合後の保存ボタンは「再保存して公開」または「再保存」と表示する。状態欄は採用元と公開状態をアイコンで示す。AI修正は星、手修正は人とペン、原文は文書、表示中は目、公開済みはチェックを使う。意味はツールチップと読み上げ用の名前で補う。入力エラーと競合は対象の編集欄のそばに表示する。

下書きと編集開始時の字幕改版はブラウザのメモリに保持する。定期取得や保存失敗でも下書きを残し、未反映の文を観客へ送らない。未保存の字幕・表示設定・AI設定がある場合は、ブラウザへ離脱確認を要求する。保存または字幕下書きの破棄で未保存の内容がなくなると解除する。ページ再読み込み・閉鎖後の復元は提供しない。

保存時に改版が変わっていれば API は 409 と最新の字幕を返す。操作画面は最新文を提示し、下書きを保持する。運用者が確認して「再保存」すると、受け取った最新改版を指定して保存する。空白だけの修正は受け付けない。

保存・表示切り替え・テスト送信中は、重複する操作を受理しない。保存中の対象行は読み取り専用にし、他の行の下書きは編集できる。背景取得中に操作が始まった場合は取得を中断し、古い結果を適用しない。

人が反映した表示文は後着の認識入力で上書きしない。入力が更新された場合は原文と入力改版を更新するが、手修正済みの字幕改版は増やさない。操作画面は表示文の `base_revision` と原文の `base_source_revision` を同時に渡して照合する。原文改版を省略するAPIクライアントでも、保存開始後の通信待ちの間に原文が変わった場合は拒否する。編集参加で受け取った別の編集者の訂正は、本文が同じ場合も人の保存として採用し、以後のAI訂正から保護する。

## マイク入力

独立配信ではUDトークとマイクを切り替え、OpenAIまたは接続先MacのApple認識を選べる。選択だけでは録音せず、明示的な開始から取得する。途中字幕は操作画面、確定字幕は既存の公開規則へ渡す。入力切替で旧認識を停止し、切断時は未確定文を保持する。準備条件・合計100円/20分の試験制限・実測と未検証の範囲は[マイク入力](microphone-input.md)を参照する。

## 入力と公開

同じ発話には同じ `utterance_id` と増加する `revision` を渡す。同じ `source_event_id` の再送は `duplicate`、受信済み以下の入力改版は `stale` として無視する。文章が同じという理由では重複排除しない。

入力の取消は `removed: true`、空の `text`、`is_final: false` で渡す。AI修正文は付けられない。手修正していない字幕の表示文を空にし、公開文を取り下げる。人が保存した表示文と公開文は保護する。受信していない発話の取消は `stale` とし、行を作らない。

上部の「新着の公開」の初期値は「自動公開」。`is_final: true` の入力と、その改版に対応するAI修正結果を自動公開する。「確認して公開」では候補を一覧に保持し、「保存して公開」の保存時に公開する。モード切り替えだけで保留中の候補を一括公開しない。どちらのモードでも、人の入力中の文は自動保存しない。

公開した文と現在の候補は別に保持する。確認モードで候補が更新されても観客画面には直前の公開文を残す。`false` の途中結果は操作画面へ保持する。途中結果を手修正して保存しても、直前の公開文を残し、確定結果で公開条件を満たしたときに差し替える。省略時の `is_final` は `true`。

「字幕を隠す」は観客への表示を止める。入力と編集は続く。非表示にした時点までの字幕と、非表示中に始まった発話は自動公開の対象から外す。「字幕を表示」ではそれらを再公開せず、新しい発話から再開する。同じ発話の後続改版や手修正も再公開のきっかけにはしない。

観客 API と SSE は表示可否と公開字幕を返す。スクロール方式では公開履歴をすべて返し、直近の字幕を選んだ場合は設定した件数に収める。方式や件数を切り替えても操作画面用の履歴は保持し、スクロール方式へ戻すと過去の公開文も含めて返す。公開字幕の順序は最初の入力の受信順。各字幕には ID・改版・表示文・発話者名を含め、原文や入力側の管理情報を送らない。非表示中は空欄、表示中で字幕がない場合は「字幕を待っています」と表示する。

SSE の切断中は直前の表示を保持し、再接続後のスナップショットで同期する。表示可否・表示設定・表示範囲の字幕ID・本文・発話者名が変わらない場合は通知を省く。本文が同じ改版更新では、最新番号は観客APIのGETと再接続時に返す。接続異常の文言表示、過去イベントの再生、全端末への到達確認は提供しない。

## AI修正結果の受け取り

入力APIに任意の `formatted_text` を付けると、原文を残したまま表示文として採用する。後から届く結果は `PUT /api/captions/{caption_id}/formatted` に `source_revision` と `text` を送る。対象原文の改版と一致しない結果は `stale` として無視する。

手修正済みの文は後着のAI結果で上書きしない。AI結果は内部に保持する。AIと人の訂正は同じ「表示文」で編集し、一覧の状態アイコンで採用元を示す。編集参加では全行共通の接続アイコンを繰り返さない。空白だけのAI結果は拒否する。生成結果の意味の正しさは自動では保証しない。

「AI設定」でGPT-6 Luna・GPT-6.1 Sol・Claude Haiku 5.5・Gemini 3.5 Flash-Liteを選択し、指定AI・費用優先・実測の速度優先を設定する。初期値はAIなし。保存した設定を次の確定入力から使い、振り分け先と依頼IDを字幕に記録する。キー設定済みなら提供元へ校正を依頼し、独立配信では公開方針に従って採用する。編集参加ではUDトークが訂正要求を受け付けた後に採用する。キー未設定・処理待ち・通信失敗を字幕の状態と訂正欄に表示し、失敗時は原文を保持する。

AIへの同時要求は2件、待機を含む字幕数は最大64件。同じ発話の更新時とモード変更時は古い処理を終了する。料金比較・時間超過・結果の照合は[AIの選択と振り分け](ai-routing.md)を参照する。「トークの背景」と直前の確定字幕を文脈として渡す。背景は最大4,000文字、過去字幕は同じ接続の最大6件・合計3,000文字。背景内の命令には従わず、本文だけを校正する。AI設定と応答時間の記録は再起動で消える。

## 単語辞書

「単語辞書」で表記・読み・誤認識されやすい表記を登録し、有効/無効の切り替え・編集・削除を保存する。自前の音声認識には表記を次の開始時に渡し、AI校正には有効な単語の情報を次の確定字幕から渡す。辞書は接続先の端末に保存され、再起動後も保持する。既存の字幕は再校正しない。保存先・競合・制約は[単語辞書](dictionary.md)を参照する。

## 別画面の表示設定

操作画面の「表示設定」で背景色・文字色、端末標準のゴシック／明朝／等幅、文字サイズ24〜96px、太さ、行間、余白、縦位置、文字揃え、直近の発話数、画面サイズ／16:9を変更する。「表示設定を反映」でサーバーへ保存し、SSEで観客画面へ送る。ページを再読み込みしてもサーバーが動作している間は設定を保持し、再起動で初期値に戻る。

発話者名は「名前の表示」で非表示・本文の前・本文の上を選べる。初期値は本文の上で、名前がない発話には名前の欄を出さない。本文の上では本文の62.5%の文字サイズを使う。名前の非表示では公開APIとSSEでも名前をnullにし、操作画面の入力名は保持する。

表示方式・文字サイズ・行間は設定の先頭に置き、詳細を開かずに選べる。表示方式はスクロールと直近の字幕。直近の字幕を選ぶと表示件数（1・2・3・5・10件）が現れる。行間は文字サイズの1.25・1.5・1.75・2倍。プレビューと観客画面は同じ描画処理を使う。プレビューは1280×800pxの基準画面を枠の幅に合わせて縮小し、文字サイズ・行間・余白・件数・比率・配置を反映する。字幕がある場合は直近の字幕を使い、入力前は配信しない表示例を明示して使う。その他の設定は「文字と配色」「配置と余白」に分け、詳細を開いて調整する。接続手順と補足は説明アイコンから開く。表示切り替えと観客画面への移動は、操作名を持つアイコンで示す。AIがオフの間はAIの候補欄を隠す。エラー・未保存・試験接続の注意は必要な状態で表示する。開くと最初の入力へフォーカスを移し、閉じると起点のボタンへ戻る。

説明欄と設定グループはクリック、Enter、Spaceで開閉する。欄ごとの開閉状態は定期取得とパネルの切り替えでも保持し、画面の再読み込みで初期状態へ戻す。設定から字幕を選択する場合と「編集中の字幕へ」の場合は、起点の設定ボタンではなく訂正欄へフォーカスを移す。

スクロール方式では公開字幕を履歴へ追加し、画面に収まらない古い字幕は上へ流れる。上へスクロールして過去の字幕を読んでいる間は、新着や訂正が届いても位置を戻さない。「最新へ」で末尾へ戻って追従を再開し、キーボードの操作先も字幕へ戻す。手動で末尾へ戻っても追従を再開する。表示方式の変更と非表示への切り替えでは読み返し状態を解除する。字幕や設定はサーバーのメモリ上にあり、再起動で消える。

直近の字幕では設定した件数を超えると古い字幕から外す。追従中は新しい発話・本文の訂正・文字サイズや行間の変更・リサイズで末尾へ移る。同じ文章の発話が続いても最新へ追従する。プレビューは新着に追従し、内容が変わらない定期取得では手動スクロールを戻さない。

幅720px以下または高さ700px以下では、表示設定とAI設定のパネル全体をスクロールする。見出しと保存操作を残し、入力項目を順に読みながら変更できる。

黒背景・白文字、白背景・黒文字、クロマキー緑の配色を用意し、任意の色も指定できる。書体は表示端末のフォントを使う。観客画面を別ウィンドウで開いてディスプレイへ移し、全画面ボタンで表示する。ブラウザから出力先のディスプレイを自動選択する機能や、仮想カメラ出力は提供しない。長い文は表示領域内でスクロールして確認できる。全画面中もポインターを動かすと解除ボタンを表示する。全画面の切り替え中は重複操作を受け付けず、失敗した場合はメッセージを表示して再試行できる。Escape による解除を検知し、切り替え状態を同期する。全画面 API が使えない環境ではボタンを表示しない。

参照したUDトークの機能と対応範囲は[字幕出力の調査](udtalk-display.md)を参照する。

## 入力 API の例

本アプリの入力 API であり、UDトークが提供する API ではない。UDトークのWeb入力AdapterはこのAPIと同じRelayの入力処理へ渡す。

```bash
curl -X POST http://127.0.0.1:24681/api/source/events \
  -H 'Content-Type: application/json' \
  -d '{
    "utterance_id": "u-001",
    "revision": 1,
    "text": "本日はありがとうございます。",
    "is_final": true,
    "source_event_id": "event-001"
  }'
```

| API | 用途 |
|---|---|
| `GET /api/session` | セッション名・表示可否・字幕数 |
| `GET /api/events` | 操作画面用の字幕一覧 |
| `POST /api/source/events` | 発話の入力・改版更新 |
| `GET /api/source/udtalk` | 実験用Web入力の接続状態・受信イベント数。観客用の応答には含めない |
| `GET /api/connection`・`PUT /api/connection` | 接続モード、受信先、字幕の形式、接続状態、編集用URLの適用 |
| `GET /closedcaption/seq`・`POST /closedcaption` | 送信先の資格情報で認証するZoom形式の字幕受信 |
| `PATCH /api/captions/{caption_id}` | `text`、`base_revision`、任意の `base_source_revision` による表示文の保存・UDトークへの送信 |
| `PUT /api/captions/{caption_id}/formatted` | 対象原文の改版に対応するAI修正結果 |
| `PUT /api/publication-mode` | 新着の自動公開・確認して公開 |
| `PUT /api/display` | 観客画面の表示設定 |
| `GET /api/ai` | AI設定・候補・料金・受信した応答時間・現在の選択先 |
| `PUT /api/ai` | AIの選び方・指定AI・候補の保存 |
| `GET /api/dictionary`・`PUT /api/dictionary` | 単語辞書の取得と改版を照合した保存 |
| `POST /api/commands` | `show`・`hide` による表示切り替え |
| `GET /api/view` | 公開用スナップショット |
| `GET /api/view/events` | 公開用スナップショットの SSE |

入力は Pydantic の厳格モードで検証する。余分な項目、文字列の改版番号、不正なコマンド、空白だけの手修正には 422、存在しない字幕の修正には 404 を返す。フィールドの詳細は[生成した OpenAPI](generated/openapi.json)を参照する。
