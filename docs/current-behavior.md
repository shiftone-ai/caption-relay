# 現行 PoC の仕様

実装確認日：2026-10-06

現在のコードとテストに対応する仕様。将来の機能・受け入れ条件は [v0.2 の設計案](design-v0.2.md)を参照する。起動方法は [README](../README.md)、責務の配置は[システム構成](../ARCHITECTURE.md)に記載する。

## 提供範囲

単一の `demo` セッションにテキストを入力し、操作画面で表示文を編集して観客へ配信する。AIへの接続は行わない。入力と同時、または後から届くAI修正結果を受け取るAPIを提供する。操作画面は字幕の一覧と原文・表示文を扱い、観客画面は初期設定で最後の公開字幕を表示し、表示設定で直近1〜10件へ変更できる。

状態はサーバーのメモリ上に置く。認証と永続化はなく、ローカルの単一プロセスで使う。

## 操作と編集

「テスト字幕を送る」は検証用の発話を入力 API へ送る。実機の音声認識や UDトーク接続の確認にはならない。

一覧は原文・表示文・状態の比較表とし、8px単位の余白、行間24px、短文の行高48pxを基準にする。長文は折り返し、切り捨てない。操作ヘッダー・公開中の字幕・列見出し・「最新へ」は一覧をスクロールしても残る。

表示文のクリックまたは編集ボタンで選択行だけを開く。編集開始時に字幕改版を保持し、最新位置への追従を止める。閉じたり別行へ移ったりしても下書きを保持し、「変更を破棄」で破棄する。「最新へ」で最新位置へ戻る。

表示文は「反映」または Ctrl / Command + Enter で保存する。Enter だけでは改行し、IME 変換中のキー操作では反映しない。競合後の保存ボタンは「再反映」と表示する。状態欄は採用元と公開状態をアイコンで示す。AI修正は星、手修正は人とペン、原文は文書、表示中は目、公開済みはチェックを使う。意味はツールチップと読み上げ用の名前で補う。入力エラーと競合は対象の編集欄のそばに表示する。

下書きと編集開始時の字幕改版はブラウザのメモリに保持する。定期取得や保存失敗でも下書きを残し、未反映の文を観客へ送らない。ページ再読み込み・閉鎖後の復元は提供しない。

保存時に改版が変わっていれば API は 409 と最新の字幕を返す。操作画面は最新文を提示し、下書きを保持する。運用者が確認して「再反映」すると、受け取った最新改版を指定して保存する。空白だけの修正は受け付けない。

保存・表示切り替え・テスト送信中は、重複する操作を受理しない。保存中の対象行は読み取り専用にし、他の行の下書きは編集できる。背景取得中に操作が始まった場合は取得を中断し、古い結果を適用しない。

人が反映した表示文は後着の入力で上書きしない。入力が更新された場合は原文と入力改版を更新するが、手修正済みの字幕改版は増やさない。保存時に照合するのは表示文の `base_revision` だけであり、原文改版の同時照合は未実装。

## 入力と公開

同じ発話には同じ `utterance_id` と増加する `revision` を渡す。同じ `source_event_id` の再送は `duplicate`、受信済み以下の入力改版は `stale` として無視する。文章が同じという理由では重複排除しない。

初期モードは「自動反映」。`is_final: true` の入力と、その改版に対応するAI修正結果を自動公開する。「確認して反映」では候補を一覧に保持し、「反映」の保存時に公開する。モード切り替えだけで保留中の候補を一括公開しない。どちらのモードでも、人の入力中の文は自動保存しない。

公開した文と現在の候補は別に保持する。確認モードで候補が更新されても観客画面には直前の公開文を残す。`false` の途中結果は操作画面へ保持する。途中結果を手修正して保存しても、直前の公開文を残し、確定結果で公開条件を満たしたときに差し替える。省略時の `is_final` は `true`。

「字幕を隠す」は観客への表示を止める。入力と編集は続く。非表示にした時点までの字幕と、非表示中に始まった発話は自動公開の対象から外す。「字幕を表示」ではそれらを再公開せず、新しい発話から再開する。同じ発話の後続改版や手修正も再公開のきっかけにはしない。

観客 API と SSE は表示可否と公開字幕の一覧を返す。各字幕には ID・改版・表示文だけを含め、原文や入力側の管理情報を送らない。観客画面は設定した数の直近の字幕を表示し、非表示中は空欄、表示中で字幕がない場合は「字幕を待っています」と表示する。

SSE の切断中は直前の表示を保持し、再接続後のスナップショットで同期する。接続異常の文言表示、過去イベントの再生、全端末への到達確認は提供しない。

## AI修正結果の受け取り

入力APIに任意の `formatted_text` を付けると、原文を残したまま表示文として採用する。後から届く結果は `PUT /api/captions/{caption_id}/formatted` に `source_revision` と `text` を送る。対象原文の改版と一致しない結果は `stale` として無視する。

手修正済みの文は後着のAI結果で上書きしない。AI候補は比較用に保持し、編集欄の「AI修正結果を確認」で読める。空白だけのAI結果は拒否する。これは受け取りと公開の仕組みであり、AIによる生成・意味の検証・提供元への接続ではない。

「AI設定」でGemini・Claude・Codexを選択し、指定AI・費用優先・実測の速度優先を設定する。初期値はAIなし。保存した設定を次の確定入力から使い、振り分け先と依頼IDを字幕に記録する。提供元への呼び出しは行わない。料金比較・速度の扱い・結果の照合は[AIの選択と振り分け](ai-routing.md)を参照する。AI設定と応答時間の記録は再起動で消える。

## 別画面の表示設定

操作画面の「表示設定」で背景色・文字色、端末標準のゴシック／明朝／等幅、文字サイズ24〜96px、太さ、行間、余白、縦位置、文字揃え、直近の発話数、画面サイズ／16:9を変更する。「表示設定を反映」でサーバーへ保存し、SSEで観客画面へ送る。ページを再読み込みしてもサーバーが動作している間は設定を保持し、再起動で初期値に戻る。

黒背景・白文字、白背景・黒文字、クロマキー緑の配色を用意し、任意の色も指定できる。書体は表示端末のフォントを使う。観客画面を別ウィンドウで開いてディスプレイへ移し、全画面ボタンで表示する。ブラウザから出力先のディスプレイを自動選択する機能や、仮想カメラ出力は提供しない。長い文は表示領域内でスクロールして確認できる。全画面中もポインターを動かすと解除ボタンを表示する。全画面の切り替え中は重複操作を受け付けず、失敗した場合はメッセージを表示して再試行できる。Escape による解除を検知し、切り替え状態を同期する。全画面 API が使えない環境ではボタンを表示しない。

参照したUDトークの機能と対応範囲は[字幕出力の調査](udtalk-display.md)を参照する。

## 入力 API の例

本アプリの入力 API であり、UDトークが提供する API ではない。実機との連携には接続仕様に合わせた Adapter が必要。

```bash
curl -X POST http://127.0.0.1:24681/api/source/events \
  -H 'Content-Type: application/json' \
  -d '{
    "utterance_id": "u-001",
    "revision": 1,
    "text": "本日はありがとうございます。",
    "is_final": true,
    "source_event_id": "event-001"
  }'
```

| API | 用途 |
|---|---|
| `GET /api/session` | セッション名・表示可否・字幕数 |
| `GET /api/events` | 操作画面用の字幕一覧 |
| `POST /api/source/events` | 発話の入力・改版更新 |
| `PATCH /api/captions/{caption_id}` | `text` と `base_revision` による表示文の保存 |
| `PUT /api/captions/{caption_id}/formatted` | 対象原文の改版に対応するAI修正結果 |
| `PUT /api/publication-mode` | 受信結果の自動反映・確認モード |
| `PUT /api/display` | 観客画面の表示設定 |
| `GET /api/ai` | AI設定・候補・料金・受信した応答時間・現在の選択先 |
| `PUT /api/ai` | AIの選び方・指定AI・候補の保存 |
| `POST /api/commands` | `show`・`hide` による表示切り替え |
| `GET /api/view` | 公開用スナップショット |
| `GET /api/view/events` | 公開用スナップショットの SSE |

入力は Pydantic の厳格モードで検証する。余分な項目、文字列の改版番号、不正なコマンド、空白だけの手修正には 422、存在しない字幕の修正には 404 を返す。フィールドの詳細は[生成した OpenAPI](generated/openapi.json)を参照する。
