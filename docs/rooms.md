# ルームの接続と字幕リセット

ホームから、以前使ったルームへの再接続と、新しいルームの登録ができます。字幕の操作は、接続後のルーム画面で行います。

## 登録・再接続

1. ホームの「新しいルームに接続」を押します。
2. ルーム名と配信先を選びます。「UDトークへ反映」では編集用の参加リンク、「独立配信」では字幕の入力元を指定します。必要ならトークの背景を記入します。
3. 「登録して接続」を押します。登録済みのルームは一覧の「接続」から開けます。設定アイコンから名前・接続先・背景を変更できます。

ルーム名は120文字、トークの背景は4,000文字まで入力できます。「𠮷」などの補助漢字も1文字と数えます。上限を超えた場合は入力内容を残し、保存前にエラーを表示します。

字幕入力の接続は同時に一つです。別のルームへ接続すると、前のルームの入力と処理中のAI校正を終了します。ルームを切り替えても、それまで受け取った字幕はルームごとに保持します。ホームへ戻る操作でも、現在の入力を終了します。

形式が不正なリンクと閲覧専用リンクは、接続を切り替える前に拒否します。保存済みの編集用リンクは画面へ返しません。接続先を変えるときだけ、新しいリンクを入力します。参加キーの有効性はUDトークの応答で判断します。

## 字幕をリセットする

1. ルーム画面の「字幕をリセット」を押します。
2. 確認画面でルーム名を確かめ、「字幕をリセット」を押します。「キャンセル」またはEscapeでは字幕と下書きを残します。

リセットは、そのルームの字幕、公開字幕、未保存の訂正、処理中のAI校正を消します。辞書・AI・表示・接続設定の未保存の下書きは残り、リセット後も編集・保存できます。ルーム名、参加リンク、背景、AI・表示・公開設定、単語辞書は残ります。UDトーク側の字幕を削除・訂正する要求は送りません。受信済みの発話が再送されても、消した字幕を復元しません。

未保存の変更がある状態でホームへ戻る場合も、破棄するか確認します。別のルームへ切り替えた後の古いタブからは保存・リセットを受け付けず、ホームへの案内を表示します。別のタブで字幕をリセットした場合は「字幕を読み直す」で復帰できます。未保存の変更があれば確認し、字幕の訂正下書きだけを破棄します。読み直しで他のルームの接続を切り替えることはありません。観客画面は、操作画面のモニターアイコンから開いてください。開いたルームの字幕だけを受け取ります。

## ルームを削除する

1. 操作画面からホームへ戻り、削除するルームの接続を終了します。
2. 一覧のごみ箱アイコンを押します。
3. ルーム名と削除内容を確かめ、「ルームを削除」を押します。

ルームの設定・字幕・訂正履歴を削除します。元に戻せません。全ルームで共有する単語辞書とUDトーク側の字幕は残ります。使用中のルームと既定の「独立配信」は削除できません。上限の100件に達した場合も、不要なルームを削除すると追加できます。別のタブから接続された場合や、保存に失敗した場合は削除を拒否し、状態を保ちます。

## 保存される情報

| 情報 | ルーム切り替え | サーバー再起動 |
|---|---|---|
| 名前・参加リンク・背景・最終利用日時 | 保持 | 保持 |
| AI・表示・公開設定 | 保持 | 保持 |
| 受信した字幕・公開した字幕 | ルームごとに保持 | 消える |
| 訂正履歴・保存結果の照合記録 | ルームごとに保持。字幕リセットで消える | 消える |
| 未保存の下書き | ホームへ戻ると破棄 | 消える |
| 単語辞書 | 全ルームで共有 | 保持 |

再起動後はホームから接続します。録音は自動で開始しません。背景はルームごとに保存し、AI校正に渡します。リセットでは直前の字幕の文脈を消します。

保存先は `CAPTION_RELAY_ROOMS_PATH`、未指定なら `$XDG_DATA_HOME/caption-relay/rooms.json` です。`XDG_DATA_HOME` も未指定なら `~/.local/share/caption-relay/rooms.json` を使います。編集用の参加リンクは権限を持つため、このファイルを公開・共有しないでください。ファイルの権限は所有者だけが読み書きできる0600にします。APIキーと字幕は保存しません。上限は100ルームです。

ローカルの単一プロセス用で、アプリ全体の認証や複数ワーカーには対応していません。設定ファイルを読めないときは、空の内容で上書きせず起動を止めます。保存失敗時もエラーを返し、字幕とリセット前の状態を保ちます。

## 検証

[バックエンドのテスト](../backend/tests/test_rooms.py)で、ルーム間の分離、設定の保存・復元、参加リンクの非公開、リセット、処理中AIの終了、古いタブと入力再送、保存失敗、削除の永続化と上限からの復帰、既定・使用中ルームの保護、観客購読の終了を検証します。UDトークへの要求は模擬HTTPで確認します。[画面のテスト](../frontend/src/rooms.test.tsx)で、登録・再接続、入力保持、確認のキャンセル、下書きの破棄、通信へのルーム情報の付与を検証します。

実ブラウザでは専用のローカルサーバーと合成のテスト字幕を使い、追加、切り替え、古いタブからの保存拒否、リセットの確認・キャンセル、再起動後の再接続を確認しました。この変更で実際のUDトークやAI提供元への接続試験は行っていません。外部連携の確認範囲は[入力接続](udtalk-input.md)と[AIの記録](ai-routing.md)を参照してください。
