# 公開前の点検

点検日：2026-10-29

ローカルPoCの公開に向けて、現在の文書・検証記録・画像と、Gitの履歴を確認した。APIキーや参加リンクの実値を、説明用の架空の値と区別して扱う。

## 公開ファイル

文書の導線を利用者向けと開発者向けに分け、[準備と起動](setup.md)へ導入手順をまとめた。個人の作業ディレクトリ、接続先名、実験用プロジェクト名、アカウント設定の承認経緯を公開文書から外した。検証記録に含まれていた絶対パスは匿名化した。

掲載画像102点を全件目視し、アカウント固有の情報が写っていた使用量画面1点を公開対象から除いた。残る101点は説明用の合成データと検証画面であり、この目視点検で個人のパス・メール・資格情報は見つからなかった。画像のメタデータも確認した。

文書と記録の文字列検索、Gitleaks、文書内の相対リンクの確認を行った。検出器で見つからないことだけで、秘密情報が存在しないとは判断しない。

## 履歴の確認

通常ブランチの履歴から個人の絶対パス、接続先名、実験用プロジェクト名とアカウント固有の記録を除いた。GitHubの過去のPR参照とキャッシュは通常ブランチとは別に管理されるため、履歴の書き換えや強制pushだけでは完全な削除を確認できない。[GitHubの削除手順](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)に従い、残存を確認して削除を依頼した。GitHub側の削除完了は未確認。

古いクローンやブランチを新しい履歴へマージすると、除いた内容が再び公開されるおそれがある。履歴を書き換えた後は新規取得したコピーを使い、必要な変更だけを移す。

## 検証の範囲

[チェックコマンド](../scripts/check.sh)はAPI型の一致、テスト、型検査、画面のビルドを確認する。画面変更は実APIと背景ブラウザで操作し、画面監査とbefore/afterの画像をPRへ記録する。

実際のUDトーク、音声認識、AIへの接続と、模擬HTTPによる試験は分けて記録する。確認済みの経路と未確認の範囲は[入力接続](udtalk-input.md)、[マイク入力](microphone-input.md)、[AI校正](ai-routing.md)、[アクセシビリティ](accessibility.md)を参照する。
